Feed layout

└── objects/sha256/<64-lowercase-hex>

Signed payload

index.json is the signed payload. Its byte representation is authoritative: consumers must not parse and reserialize it before verification. It declares the catalog identity, monotonic revision, minimum app version, and a sorted inventory of logical paths mapped to content-addressed objects.

Detached signatures

index.signatures.json identifies the SHA-256 of the exact index bytes and carries one or more raw Ed25519 signatures. A consumer accepts a signature only when its key ID and public key appear in the application's global RGM trust set. Catalog identity does not select or grant trust.

Payload contract

A complete generation contains catalog.json, one resolve.json per title, one profile.json per advertised title version, and only media referenced by that catalog. Cores and game binaries are not catalog payloads. RGM ships its Core in the application and imports game files manually from a location selected by the user.

Transport and cache

The index may be hosted at any public HTTPS location. Every object must resolve beneath that feed's HTTPS root and remain on the same origin through redirects. Each object is bounded to 8 MiB and checked against its signed size and SHA-256 before parsing. A consumer writes a new immutable generation, verifies it completely, then replaces a small active pointer atomically. A failed refresh never replaces the last known good generation.

Rollback resistance

Consumers retain a high-water revision per catalog identity. A lower revision is rejected. Reusing an accepted revision with different index bytes is also rejected. Moving the same signed feed between HTTPS origins does not change its identity or grant a new origin signing authority.
