Verification policy

  1. Require the exact public HTTPS URL bound into the app.
  2. Fetch index.json and its sibling index.signatures.json.
  3. Verify a signature over the exact index bytes against the app's global RGM key set.
  4. Bind the exact catalog version, index hash, envelope hash, and key ID to each app release.
  5. Reject a changed version or changed bytes at an accepted version.
  6. Fetch same-origin content-addressed objects and verify signed byte sizes and SHA-256 hashes.
  7. Activate a complete generation atomically; retain the last verified generation on failure.

Current application releases accept only their exact bound catalog version. Retired release audit remains in reachable Git history and is not served by this site.

Key rotation

A client update may pin an old and a new public key concurrently. Feeds are then signed by both keys before a later client update removes the retired key. Private keys are kept outside source repositories and publication output.
